Failures retained, and what changed
1. UTF-8 save/reopen closure (independent Node reproduction of pre-fix code):
   createProject(); replace its first track notes with 20,000 distinct IDs,
   midi=60,start=0,duration=1,velocity=90,channel=0,lyric='汉'.repeat(256);
   set nextId=20001, then validateProject -> projectJson -> parseProject.
   BEFORE: valid_notes=20000 serialized_bytes=19049484
           reopen=FAIL 工程文件超过 8 MiB
   AFTER: validation rejects the candidate before Editor installs it:
           工程保存后将超过 8 MiB；本次操作未应用，请减少音符、控制点或歌词
   The accepted-state invariant now includes canonical UTF-8 serialization size.
   Test: 'the accepted editor state always fits its own UTF-8 save/reopen limit'.

2. Same-frame repedalling (independent Node reproduction):
   4-beat project at 120 BPM, sine C4 start0/duration1/velocity90, default project
   and track gain; sampleRate8000. Baseline CC64 @beat0=127. Comparison adds
   CC64 @beat2=0 then @beat2=127. Compare left samples; measure RMS after frame 10000.
   BEFORE: differentSamples=0; postPedalChangeRms=0.019639960665065972;
           voiceFramesHeld=16000; voiceFramesChange=16000.
   The release edge had disappeared because all same-frame CC were compacted.
   AFTER: differentSamples=7999; postRms=0; voiceFrames=8640.
   CC64 now retains release edges and the 640-frame sine release tail. Keys
   still down and notes released at the same tick follow the explicit ordering.
   Test: 'same-frame repedalling releases old held notes but not keys still held or new NoteOffs'.

3. MIDI wire / DSP simultaneous-event ordering:
   C4 start0/duration1, CC64 down atbeat1. BEFORE, exported bytes contained
   80 3c 00 00 b0 40 7f (NoteOff then same-tick pedal-down), while the DSP kept
   sounding (RMS over 1.0–1.5 seconds=0.019649326382178197 at 8 kHz).
   AFTER, stable same-tick CC source order precedes NoteOff, then NoteOn;
   exported bytes contain b0 40 7f 00 80 3c 00. The importer visibly reports
   this normalization when source same-tick pedal/NoteOff order could differ.
   Independent wire-order and importer-warning tests protect the contract.

4. Staff-specific MusicXML transpose:
   Cold review found transpose@number='2' would affect staff1 as well. V2 now
   explicitly rejects staff-specific transpose instead of silently changing pitch.
   The browser fixture has two staves, C on staff 1 and D on staff 2, with a -2
   chromatic transpose restricted to staff 2; rejection matches /按谱表.*移调/.
   This path was initially a code-reading finding, then covered in the real
   browser DOMParser 11-fixture suite. General unnumbered transpose remains supported.

5. Browser held-space failure:
   Original run: 11/13; held-space repeat toggled playback off on BOTH URL
   prefixes. Other browser checks passed. Raw failed output is retained below.
   The keyboard handler now ignores repeat for transport/edit shortcut actions;
   arrow-key stepping remains deliberate. Final run: 13/13.
