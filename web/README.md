# Classical DAW Web Alpha v2

这是面向古典音乐草稿的纯静态网页工作站：导入乐谱、分别编辑声部、合成试听，并保存可继续编辑的工程。无需账号、后端、构建工具或外部 CDN；应用没有文件上传接口、统计脚本或外部音源下载，音乐数据在浏览器本地处理。

网页使用自己的 JavaScript 工程模型和合成器。它尚未接入仓库的 C++ / CoreAudio / AU 引擎，不能加载 Pianoteq、SWAM 或其他本机插件；也没有 AI 作曲模型、真实采样音库、专业混音链或谱面排版。当前音色是原创的合成钢琴、合成弦乐与纯音，用于检查结构、音高、节奏和声部关系。

## 可以做什么

- 多声部钢琴卷帘，编辑音高、起点、时值、力度、MIDI 通道和歌词；支持新增、删除、复制粘贴及键盘移动音符。视窗可在长谱中前后移动，音域覆盖 MIDI 0–127。视窗不是工程长度限制，未显示的音符仍保留。
- 每轨选择合成音色、增益、声像、静音与独奏；静音优先于独奏。
- 编辑分段速度和拍号图，以及按声部、MIDI 通道隔离的阶梯控制点。试听解释 CC7 音量、CC10 声像、CC11 表情和 CC64 延音踏板；其他 CC 保存在工程中并随 MIDI 导出，不在试听中执行。
- 音符、控制器、混音及工程替换使用同一撤销/重做历史。历史有界，最多保留 32 个状态，并受存储预算约束；保存的 JSON 不包含撤销栈。
- 保存、重开网页 JSON v2 工程；兼容迁移旧网页 v1 草稿，但无法恢复旧版本已经裁掉或量化的信息。非法导入或超限编辑会报错并保留当前工程，不会静默截断内容。
- 各浏览器标签分别保存恢复副本；未处理的旧副本不会被新标签的编辑覆盖，可恢复、下载或显式丢弃。浏览器配额、隐私模式或清理网站数据会影响本地副本，因此应定期下载独立 JSON 工程。

工程上限为 **16 个声部、20,000 个音符、50,000 个控制器事件、4,096 个四分音符拍**。速度为 20–400 BPM，拍号分子为 1–32，分母支持 1、2、4、8、16、32。导入文件上限为 **8 MiB**；每个被接受的工程状态还必须能按实际 JSON 下载格式序列化到 8 MiB 内，保证保存后能够重新打开。因此各数量上限不能理解为必定能同时用满。

## 试听与 WAV

试听和 WAV 导出都由真实的模块 Worker 调用同一个确定性合成器，生成 **48 kHz 立体声**缓冲；WAV 为 PCM16。试听在合成完成后通过 Web Audio 播放，界面可取消计算；编辑会停止当前试听。它尚不是边发声边编辑的本机实时 AU 路径。

每次选择的试听/导出片段最多 **120 秒**，不是把整份工程限制为 120 秒。还会检查最多 128 个同时发声的音（包括踏板保留和尾音），以及 8,000 万“发声数 × 采样帧”的计算预算。超限时应缩短片段或减少参与声部，不会自动裁曲。输出报告削波采样数，发生削波时应降低主增益。

控制点目前是阶梯变化，不是平滑自动化曲线。同一时刻遵循统一规则：**CC 按源顺序执行，然后 NoteOff，然后 NoteOn**。同键的后续起音会结束先前发声；这是一套有限的合成试听语义，不代表所有外部插件的行为。

## 文件互换边界

优先用网页 JSON 保存完整的网页工程。MusicXML 和 MIDI 都是互换格式，不包含所有外部软件的记谱、路由、音源状态或音色。

**MusicXML：**支持未压缩的 `score-partwise` XML、多声部、多 voice、和弦、休止、跨小节延音、弱起、任意小节标号、`backup`/`forward`、变速变拍和整声部半音移调。不等时值的和弦导出为具有独立游标的 voice，避免后续音符位置漂移。允许外部 DOCTYPE 声明但不解析或请求外部 DTD；ENTITY 和内部 DTD 子集会被拒绝。`.mxl` 需先解压或转换。

- 反复、房子和跳转尚未展开，按书写顺序演奏一次，并显示导入记录。
- 倚音没有定义借时播放方式，会明确拒绝；微分音、八度移位线、非常规定弦和带 `number` 属性的谱表专属移调也会拒绝，避免悄悄改动音高或时值。
- 多段歌词只保留第一段并提示；奏法、装饰音型、延长记号及渐强弱记号不自动展开，相关限制可见于导入记录。未声明起始速度时以 96 BPM 试听，并明确标为试听假设。
- 标准音符、速度、拍号和默认通道踏板之外，网页的 CC 与混音参数通过具名 `miscellaneous-field` 扩展保存。第三方记谱软件可能忽略该扩展；不承诺完整记谱或控制器互换保真。

**MIDI：**支持 Type 0/1 的 PPQ 文件，保留音符、轨内通道、所有 CC、后续速度与拍号变化；不支持 Type 2 或 SMPTE 时间格式。未声明起始速度时使用 MIDI 标准默认 **120 BPM**，后续速度事件保持原位置。同 tick 的冲突速度按源文件顺序采用最后一个并提示。

- 导出为 Type 1、960 PPQ，每个声部分配独立 MIDI Port，避免网页独立声部在外部软件中仅因同通道而串扰。外部 DAW 仍需核对端口与音源路由；网页的主/轨道增益、声像、静音和独奏不作为完整混音写入 MIDI。
- 同通道同音高重叠按 LIFO 配对，并提示这一约定。不能用该约定保真的交错重叠会拒绝 MIDI 导出，可继续保存 JSON 或 MusicXML。
- 检测到同通道同拍的 CC64 与 NoteOff 时，会明确报告向“CC → NoteOff → NoteOn”规则归一化；不声称保留原 MIDI 的放键/踏板先后行为。
- Program Change、弯音、触后、SysEx 等未保存或执行的信息会报告。部分文字、松键力度与其他元数据也不保留。

MusicXML/MIDI 导入按 960 PPQ 归一化，必要时提示舍入；不会强制吸附到卷帘的四分之一拍网格。导出也使用 960 PPQ，非 tick 对齐的编辑可能产生最多半个 tick 的端点舍入；MIDI 速度还受整数微秒格式的精度限制。请保留原始文件并阅读导入记录。

## 本地运行与静态部署

在仓库根目录执行：

```bash
python3 -m http.server 8080 --directory web
```

打开 <http://localhost:8080/>。页面依赖 ES modules 和模块 Worker，应通过 HTTP/HTTPS 打开，不要直接双击 `file://` 文件。

页面支持站点根路径和子目录部署，无构建命令、后端数据库或服务端密钥要求。完成源码提交后可生成只含公开程序的发布包：

```bash
python3 scripts/package_web_release.py --output out/web-release
```

脚本拒绝覆盖已有目录和归档，也拒绝打包与 HEAD 不一致的网页文件。生成目录和同名 `.zip`；`release.json` 记录源码提交、来源与发布文件的 SHA-256，页面源码/许可证链接固定到该提交。只包含明确列出的网页文件与许可证，不包含测试、Git 历史、本地乐谱、录音或插件状态。

将发布目录的内容放到静态 HTTPS 主机，保持模块、Worker、样式及图标的相对路径，并让 `.mjs` 使用 JavaScript MIME 类型。HTTP 响应不要强制下载模块；建议对 HTML 与模块设置需重新验证的缓存策略，避免旧页与新模块混用。`release.json` 可用于确认主机上的实际版本。

部署不要求运行 GitHub Actions。Pages workflow 已改为仅手动触发，当前这次发布不调用它。此工程遵守当前费用约束：**不要反复触发或重试 workflow，也不要把推送 `main` 当作修复部署的步骤**。若日后采用 GitHub Pages，应先核实仓库当前部署设置与已有授权，再选择一次明确的发布操作。

## 本地验证

在仓库根目录使用已有的 Node.js 运行三个测试文件：

```bash
node --test web/tests/core.test.mjs web/tests/formats.test.mjs web/tests/audio.test.mjs
```

浏览器回归脚本使用**已经安装**的 Playwright 模块与 Chromium，不安装依赖、不下载浏览器、不调用 GitHub Actions。若模块或浏览器不在默认查找位置，可按实际路径设置环境变量；以下是 macOS Chrome 示例：

```bash
PLAYWRIGHT_MODULE_PATH=/absolute/path/to/node_modules/playwright \
PLAYWRIGHT_CHROMIUM_EXECUTABLE="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
WEB_BROWSER_OUTPUT=out/web-alpha-browser \
node scripts/check_web_browser.mjs
```

脚本会自行启动临时 localhost 服务，分别验证根路径与 `/classical-daw/` 子目录，写出 `browser-report.json` 和桌面/移动视图截图。主要流程使用真实模块 Worker 和 PCM 渲染器、替换 AudioContext 的设备调度以比对缓冲。另有一项原生 Web Audio 烟测，验证 resume、音源启动、时钟推进及停止；Chrome 始终使用 `--mute-audio`。这些验证不能代替真人听感或物理扬声器验收。独立 MusicXML DOM 回归页位于 `tests/fixtures/formats-browser.html`，可通过本地静态服务打开。
